## 使用方法

当用户要求"审查/检查/看看改动"时，按以下步骤操作：

1. 先用 `exec` 跑 `git status --short` 与 `git diff` 摸清改了哪些文件；
2. 用 `read_file` 把改动涉及的文件完整读一遍——只看 diff 容易漏掉上下文；
3. 按下面三类问题逐条检查，每条都给出**文件位置 + 问题 + 建议**；
4. 用 `exec` 跑一次项目自带的检查（如 `python -m py_compile`）验证语法。

## 检查清单

- **正确性**：边界条件、空值、异常路径；改动的调用方是否同步更新。
- **一致性**：新代码是否沿用了项目既有的命名、注释语言和错误处理方式。
- **安全性**：有没有把密钥、token、隐私内容写进代码或日志。

## 注意事项

- 不要读 `.env` 之类的隐私文件，也不要把它里面的内容复述出来。
- 只报真实存在的问题，不要为了凑数提"可以更好"的主观建议。
- 结论先行：先说有没有问题，再逐条展开。
